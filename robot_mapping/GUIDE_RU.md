# Гайд: как запустить построение карты на роботе

Пошаговая инструкция для RobotMK1 (Raspberry Pi 5 + OAK-D Lite + LiDAR STL-27L + Hailo-8).
Робот при этом никуда не едет — карту строим, либо стоя на месте, либо перенося робота руками.
Подробные справочники на английском: `SETUP_AND_RUN.md`, `CALIBRATION.md`, `DEPENDENCIES.md`.

---

## 0. Что нужно иметь

* Raspberry Pi 5 (8 ГБ) с Raspberry Pi OS 64-bit (Trixie), монитор + клавиатура или SSH с рабочего ПК.
* Интернет на Pi (для `apt`, `pip`, Docker-образа).
* Подключённые по USB: OAK-D Lite (**обязательно в синий USB 3 порт, кабель USB 3**),
  USB-адаптер лидара из комплекта D800, плата Niumo V5 (Type-C). Лидар и плата — в любые порты.
* Рулетка (для замера положения датчиков), коробка или книга (для калибровки лидара),
  ровная стена в 1,5–2,5 м (для калибровки камера↔лидар).
* Карта microSD с запасом 10+ ГБ свободного места (Docker-образ ~3 ГБ, карты ~50–300 МБ каждая).

---

## 1. Скопировать папку на Pi

С ПК (PowerShell или Git Bash), `pi@robot.local` замените на своего пользователя/адрес:

```bash
scp -r D:\PyCharmProjects\RobotMK1_Detection_and_Map_Creation\robot_mapping pi@robot.local:~/
```

Дальше всё делаем **на Pi**, в терминале, внутри папки:

```bash
ssh pi@robot.local
cd ~/robot_mapping
```

> Если файлы копировались через Windows и скрипты не запускаются с ошибкой `bad interpreter`,
> выполните `sed -i 's/\r$//' install.sh mappers/rtabmap/entrypoint.sh` (уберёт CRLF).

---

## 2. Установить всё одной командой

```bash
chmod +x install.sh
./install.sh --all
```

Что делает (30–60 минут, самое долгое — сборка Docker-образа RTAB-Map):

1. ставит системные библиотеки (`apt`);
2. ставит udev-правила → лидар всегда виден как `/dev/robot_lidar`, плата как `/dev/robot_mcu`;
3. создаёт виртуальное окружение `.venv` и ставит Python-пакеты из `requirements.txt`;
4. ставит `hailo-all` (драйвер и рантайм Hailo-8);
5. ставит Docker и собирает образ `robotmk1/rtabmap:jazzy`.

Варианты: только Python-часть — `./install.sh`; без Hailo — `./install.sh --docker --build-image`.

После установки **выйдите из сессии и зайдите снова** (или `sudo reboot`) — иначе не применятся
группы `dialout`/`docker`. Затем **каждый раз перед работой**:

```bash
cd ~/robot_mapping
source .venv/bin/activate
```

Модель для Hailo (только если хотите использовать `--hailo`): скачайте `yolov8s.hef`, собранный
для **Hailo-8** (не 8L), из Hailo Model Zoo (https://github.com/hailo-ai/hailo_model_zoo,
раздел Object Detection) и положите в `models/yolov8s.hef`.

## 3. Проверить, что все датчики отвечают

```bash
ls -l /dev/robot_lidar /dev/robot_mcu     # обе ссылки должны существовать
python run.py check
```

Ожидаемый результат (главное):

```
=== OAK-D Lite ===
  mxid ...  usb SUPER  imu BMI270 ...
  frames: 58 in 4.0 s = 14.5 fps
  depth: 71% valid pixels, median distance 2.1 m
  accel in body frame [+0.10 -0.05 +9.78]  <- expect ~[0, 0, +9.8] when level
=== LiDAR (LDROBOT) ===
  scans: 40 in 4.0 s = 10.0 Hz ... bad CRC 0
  points per revolution: 2160
  inside the forward 180 deg FOV: 1080 points
=== STM32 main board ===
  telemetry: 150 packets in 3 s = 50 Hz
  note: encoders report 0 - expected with the current firmware
```

Если что-то помечено `WARNING`/`FAIL` — см. раздел 10 ниже, дальше не идите, пока не исправите.
`usb HIGH` вместо `SUPER` = камера сидит на USB 2 — смените порт/кабель.

## 4. Записать геометрию робота в `config/robot.yaml`

Откройте `nano config/robot.yaml`. Система координат: **x вперёд, y влево, z вверх**, начало —
на полу под серединой задней оси. Замерьте рулеткой и впишите (в метрах):

```yaml
camera:
  mount: {x: 0.05, y: 0.0, z: 0.22, roll: 0.0, pitch: 0.0, yaw: 0.0}
lidar:
  mount: {x: 0.12, y: 0.0, z: 0.15, roll: 0.0, pitch: 0.0, yaw: 0.0}
```

* `camera.mount` — центр среднего (цветного) объектива OAK-D: насколько он впереди задней оси (`x`)
  и на какой высоте над полом (`z`). `pitch > 0` = камера смотрит вниз.
* `lidar.mount` — центр вращающейся «шайбы» лидара. У вас он чуть впереди и ниже камеры, поэтому
  `lidar.x > camera.x`, `lidar.z < camera.z`.

Точность ±5 мм достаточна: углы и смещения потом уточнят калибровочные утилиты. Остальные поля
(`forward_angle_deg`, `imu_rpy_deg`) заполнят утилиты из шага 5.

## 5. Калибровка (один раз, и после любого сдвига датчиков)

### 5.1 Куда «смотрит» лидар (2 минуты)

Поставьте коробку/книгу в 30–60 см **строго перед** роботом по его оси; ближе метра больше ничего
не должно быть.

```bash
python run.py lidar-view --find-forward --apply
```

Утилита найдёт ближайший объект и запишет его угол в `lidar.forward_angle_deg`. Проверка:

```bash
python run.py lidar-view
```

Откроется полярный график: «вперёд» — вверху, предметы слева от робота должны быть слева.
Если зеркально — лидар стоит вверх ногами: поставьте `lidar.clockwise: false`. Серые точки —
задняя половина, которую мы отбрасываем (`fov_deg: 180`). Убедитесь, что среди синих точек нет
самого робота (точки на расстоянии < 15 см); если есть — уменьшите `fov_deg` до 160 или
увеличьте `min_range_m`.

### 5.2 Ориентация IMU камеры (1 минута)

У OAK-D Lite ориентация IMU отличается от партии к партии, поэтому её надо измерить:

```bash
python run.py calib-imu --apply
```

Поза A: камера горизонтально, смотрит вперёд, робот неподвижен — Enter, ждём 3 с.
Поза B: наклоните робота/камеру **носом вниз на 20–60°**, держите неподвижно — Enter, 3 с.
В `robot.yaml` запишутся `camera.imu_rpy_deg` и `imu_verified: true`. Проверка — `python run.py check`
должен показать `accel in body frame ≈ [0, 0, +9.8]`.

### 5.3 Камера ↔ лидар и наклон камеры (5 минут)

Поставьте робота в 1,5–2,5 м перед ровной стеной; в кадре камеры должно быть что-то
несимметричное — вертикальная палка (швабра) в метре впереди и полуметре сбоку, коробка или
угол комнаты. Робот неподвижен.

```bash
python run.py calib-lidar-camera
```

Утилита печатает:

* по плоскости пола — поправки `camera.mount.roll / pitch / z`;
* по сравнению среза глубины на высоте лидара со сканом — поправки `lidar.mount.x / y / yaw`
  и качество совпадения `ICP fitness` (должно быть > 0,8).

Если наклон пола > 1° — сначала примените поправки камеры и повторите; затем запишите всё:

```bash
python run.py calib-lidar-camera --apply --apply-camera
```

## 6. Пробный запуск без сохранения

```bash
python run.py fusion --no-record --viz
```

Откроется окно: слева RGB с ключевыми точками и глубина, справа вид сверху (жёлтое — препятствия,
серое — пол, красное — текущий скан лидара, зелёное — траектория). В терминале раз в секунду:

```
 9.8 fps | x +0.41 y -0.02 yaw +3.1 | VO ok  312/402 | ICP 0.97* | KF 12 loops 0 | voxels 48120 | dets 0 | no-record
```

Что смотреть: `VO ok` (не `lost`), `ICP` близко к 1 и со звёздочкой (лидар подтверждает
положение), красные точки лидара лежат на стенах, которые видит камера. Медленно поверните робота
на месте — стены на виде сверху должны оставаться прямыми. `q` — выход.

То же для RTAB-Map (первый запуск контейнера ~20–30 с):

```bash
python run.py rtabmap --no-record --viz
```

Откроется окно `rtabmap_viz` с картинкой, облаком и графом. Красный экран = потеряна одометрия —
двигайтесь медленнее, проверьте глубину.

## 7. Построить настоящую карту

Самый простой способ — интерактивное меню:

```bash
python run.py
```

Выберите `1) rtabmap` (основной вариант) или `2) fusion`, укажите папку (по умолчанию
`maps/<дата_время>`), ответьте «Y» на **save the map (map recording)**, дальше — по вкусу
(live view, Hailo, raw-запись).

То же из командной строки:

```bash
python run.py rtabmap --out maps/room1 --record --viz          # RTAB-Map
python run.py fusion  --out maps/room1 --record --viz --hailo  # fusion-картограф с Hailo-8
```

Как двигать робота (руками или на месте):

* камера **по центру** (скрипт сам шлёт `@R` плате), сервоприводы во время картографирования не трогать;
* медленно: ≤ 0,3 м/с, повороты ≤ 30°/с; в кадре должны быть текстурные поверхности, не
  упирайтесь в голую стену ближе 30 см;
* обойдите комнату и **вернитесь в точку старта, глядя в ту же сторону** — так сработает замыкание
  петли и уйдёт накопленный дрейф;
* `p` — пауза/продолжение добавления в карту (трекинг продолжается; удобно, когда нужно
  переставить робота или кто-то прошёл в кадре), `q` или `Ctrl+C` — закончить и сохранить.

Флаг `--6dof` — если робот не на полу (носите в руках с наклонами); для езды по полу не нужен.

## 9. Проверить конвейер без датчиков

Синтетическая комната позволяет прогнать весь fusion-картограф (одометрия, лидар, замыкание петли)
хоть на Pi, хоть на ПК:

```bash
python run.py synth --out maps/synth/raw
python run.py fusion --replay maps/synth/raw --out maps/synth --record
```

Так же можно переиграть реальную запись, сделанную с `--raw`:
`python run.py fusion --replay maps/room1/raw --out maps/room1_v2 --record`.

## 10. Если что-то не так

| Симптом | Что делать |
|---|---|
| `check`: камера не найдена | синий USB 3 порт, кабель USB 3, `lsusb \| grep 03e7`; переткнуть; udev-правило стоит? |
| `no LiDAR packets` | скорость 921600 для STL-27L (230400 для LD19/LD06) в `serial.lidar_baud`; лидар крутится? `ls -l /dev/robot_lidar` |
| точки лидара повёрнуты / сзади | шаг 5.1 (`forward_angle_deg`), флаг `clockwise` |
| `[imu] WARNING: configured camera.imu_rpy_deg looks wrong` | шаг 5.2 |
| стены наклонены, пол «стоит» препятствием | шаг 5.3 (`camera.mount.pitch/roll/z`) |
| `VO lost` почти всегда | темно, нет текстуры, слишком быстро; мало валидной глубины (`check` показывает %) |
| RTAB-Map: `Did not receive data since 5 seconds` | `python run.py rtabmap --shell`, внутри `ros2 topic hz /oak/rgb/image_rect /scan /imu/data` |
| `docker: permission denied` | `sudo usermod -aG docker $USER`, перелогиниться |
| окно `--viz` не открывается по SSH | запускайте из терминала на рабочем столе Pi (или `export DISPLAY=:0`, `xhost +local:`) |
| ничего не сохранилось | был `--no-record`; либо процесс убит — завершайте только `q`/`Ctrl+C` один раз и ждите экспорт |

Важно знать: прошивка платы сейчас всегда отдаёт нулевые счётчики энкодеров (`Encoder_Updata()`
не вызывается), поэтому одометрия колёс не используется — карта строится по камере, IMU и лидару.
Это ожидаемо и на работу не влияет.
